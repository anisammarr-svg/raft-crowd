# RAFT-CrowdFlow: code from the beginning

This is a new reference implementation based on the manuscript's architecture. It makes previously unspecified choices explicit. It does **not** reproduce the rejected paper's AUC values or validate crowd-crush prediction. The original notebook/PDFs and the separate LiteCrowdRelNet repository are unchanged.

## Start in Colab

Open `output/jupyter-notebook/RAFTCrowdFlow_from_scratch.ipynb` in Colab and select a GPU runtime. The notebook embeds this package, configuration, instructions and synthetic tests with source checksums, so cloning the repository is optional. Follow the cells to install dependencies, check the implementation, supply frame data/labels, extract flow, calibrate, evaluate and display the six-panel image.

The notebook is generated by `python scripts/build_raftcrowd_notebook.py`; edit reusable sources and rebuild, rather than editing embedded source by hand. Its source pins preserve the exact generated implementation. New code means a new extraction cache.

## Local or Linux GPU setup

Use a clean Python environment and install a compatible PyTorch/Torchvision pair for your GPU. Then install the declared dependencies:

```sh
python -m pip install -r requirements-raftcrowd.txt
python scripts/raftcrowd.py --help
```

The dependency ranges are not a tested lockfile. Actual versions, backend, hardware, precision, command, configuration, input hashes and source hashes are recorded during extraction. Pin the actual working environment before a research run. The default 360 x 640 RAFT-large inference can require substantial GPU memory; CPU is supported explicitly but slow. No full RAFT or GPU run was performed in the implementation environment.

## Data layout

Supply a CSV manifest with exactly these columns. Paths are relative to the manifest file, or absolute. Each frame directory contains chronologically sorted, zero-padded PNG/JPG filenames. Use distinct `group` values across splits for the actual independent source units (camera/sequence/scene as appropriate); software cannot infer undisclosed related sources.

```csv
id,split,group,frames,labels,density
train001,train,source_train,train001/frames,,
val001,val,source_val,val001/frames,val001/labels.npy,
test001,test,source_test,test001/frames,test001/labels.npy,
```

Labels are one-dimensional binary `.npy` arrays of length N: 0 normal, 1 anomalous, aligned to input frame filenames. Derive these from the dataset's actual annotations; never create arbitrary labels for research results. Omitted train labels declare normal-only data; validation and test labels are required. Each of the pooled validation and pooled test sets needs both classes after the first frame is excluded. Multiple datasets should have separate manifests/caches, not pooled dataset scores.

To decode a local video into frames:

```sh
python scripts/raftcrowd.py video-frames --video path/to/video.mp4 --out data/clip_frames
```

This extracts every decoded frame and records diagnostic decoder timestamps, not a validated native-PTS alignment. For standard benchmarks, use the official frame files and exact official annotation alignment whenever available.

## Run the complete workflow

Edit the example manifest/configuration for your actual files. Defaults select CUDA and the explicit pretrained `C_T_V1` RAFT-large weights. The weights download on the first model construction. Set `device` to `cpu` if needed.

```sh
python scripts/raftcrowd.py extract --manifest configs/raftcrowd_manifest.example.csv --config configs/raftcrowd.json --out results/raftcrowd/cache
python scripts/raftcrowd.py calibrate --cache results/raftcrowd/cache --out results/raftcrowd/model.json
python scripts/raftcrowd.py evaluate --cache results/raftcrowd/cache --model results/raftcrowd/model.json --out results/raftcrowd/evaluation
python scripts/raftcrowd.py visualize --cache results/raftcrowd/cache --model results/raftcrowd/model.json --video-id test001 --frame-index 1 --out results/raftcrowd/panel.png
```

Outputs are exclusive-create: choose a new directory/path for another run. Interrupted extraction leaves a partial cache without a completion receipt; it cannot be calibrated. This version does not implement cache resumption. All flow/cue maps are cached per pair, so budget storage before a full benchmark. At 360 x 640 each float32 scalar map is about 0.92 MB before compression; this implementation stores several maps plus two-channel flow and labels per pair. Start with a small **separate** pilot manifest before scheduling full extraction.

The model JSON stores training-derived normalization scales, validation-chosen thresholds for every method and validation predictions. Test evaluation writes `metrics.json`, `frame_scores.csv` and a checksum receipt, including pooled and per-video metrics. AUC/EER are fractions, not percentages. Single-class per-video AUC/EER are null with a reason; the pooled test set requires both classes. First frames have no score: pair `(t,t+1)` is evaluated against label `t+1`.

## What is implemented

- One frozen RAFT field per observed frame pair, RGB preprocessing, padding removed by cropping.
- Gaussian smoothing of numeric flow; deterministic motion-vector clustering.
- Nonnegative compression, circular directional variance, regional magnitude variance.
- Training-only cue normalization and equal-weight CFI fusion; top-fraction frame scoring.
- Flow-magnitude-only baseline, individual cues, leave-one-cue-out controls, and a no-segmentation control with its own training-derived variability scales.
- Validation-only threshold selection; fixed-threshold test F1, pooled ROC-AUC/EER and per-frame output records.
- Six panels from the same cached flow: source RGB, flow color, CFI, magnitude, compression and motion groups.

No anomaly network is trained: RAFT is pretrained and frozen; "training" fits cue scales. There is no optimizer or epoch schedule to invent.

## Optional pedestrian density

The default is a **motion-only CFI**. To add the manuscript's fourth term, set `density_mode` to `external` and provide a density directory for every manifest row. Supply `source_frame_stem.npy` for each pair's first frame. Each map must be finite, nonnegative and already aligned to the configured resized H x W grid. It is multiplied by flow magnitude. Automatic resizing is rejected because count-density transforms require a declared area correction. Record the density estimator, checkpoint, training data, units and transformations separately.

No Gaussian-blurred flow is presented as pedestrian density. Until real density maps are supplied, pressure experiments are unavailable; the default `full` name means **all active motion cues**, not the paper's unverified four-term configuration. No temporal mask warping is implemented in this first version. K-means can group spatially disconnected motion, and the moving-pixel gate can miss near-static crowd compression. Image divergence is not physical pressure.

## Validation and method notes

Run the synthetic CPU suite without installing PyTorch:

```sh
# Linux / Colab
PYTHONPATH=src python -m pytest -q tests/test_raftcrowd_*.py
```

```powershell
# PowerShell
$env:PYTHONPATH = 'src'
& '.venv/Scripts/python.exe' -m pytest -q tests/test_raftcrowd_*.py
```

These tests check cue mathematics, metrics, split/label admission and the extraction-to-evaluation workflow using an explicitly synthetic injected estimator. They do not establish RAFT accuracy, real-data performance, novelty or deployment speed.
